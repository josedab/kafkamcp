# Releases & Supply-Chain Verification

KafkaMCP releases are built and published by [GoReleaser v2](https://goreleaser.com)
from a signed git tag via `.github/workflows/release.yml` using
`goreleaser/goreleaser-action@v7` pinned to **v2.17.0**. Every release includes
verifiable supply-chain metadata produced **without any long-lived signing keys**
(all signing uses short-lived Sigstore/Fulcio certificates via GitHub OIDC).

## What every release contains

| Artifact | Purpose |
| --- | --- |
| `kafkamcp_<version>_<os>_<arch>.tar.gz` / `.zip` | Prebuilt binaries |
| `checksums.txt` | SHA-256 checksums of all archives **and** their SBOMs |
| `checksums.txt.sigstore.json` | Sigstore bundle — sig + short-lived cert + Rekor log entry (replaces the separate `.sig`/`.pem` pair from earlier releases) |
| `<archive>.sbom` | SPDX-JSON SBOM per archive generated by syft; included in `checksums.txt` |
| GitHub build provenance attestation | SLSA-compatible provenance for archives and `checksums.txt`, issued by `actions/attest-build-provenance@v3` |
| `ghcr.io/josedab/kafkamcp:<version>` | Multi-arch container image |

> **Bundle vs. separate files:** The `.sigstore.json` bundle is the Sigstore
> bundle format introduced in cosign ≥ 2.x — a single JSON file containing the
> base64-encoded signature, the short-lived Fulcio certificate, and the Rekor
> transparency-log entry. Older releases (before this config change) shipped
> separate `checksums.txt.sig` and `checksums.txt.pem` files; those artifacts
> will not be present in releases built from the current config.

## Verify a download

Download the release archive, `checksums.txt`, and `checksums.txt.sigstore.json`
from the [GitHub Releases page](https://github.com/josedab/kafkamcp/releases).

### 1. Checksums

Verify the archive (and SBOM if downloaded) against the checksum file:

```bash
sha256sum --check checksums.txt
```

On macOS use `shasum -a 256 --check checksums.txt`.

### 2. Checksum signature (Sigstore bundle)

Requires [cosign ≥ 2.0](https://docs.sigstore.dev/cosign/system_config/installation/).

```bash
cosign verify-blob \
  --bundle checksums.txt.sigstore.json \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/josedab/kafkamcp/\.github/workflows/release\.yml@.*$' \
  checksums.txt
```

Expected output on success:

```
Verified OK
```

> **What this proves:** The `checksums.txt` file was signed by a GitHub Actions
> runner executing the `release.yml` workflow in the `josedab/kafkamcp`
> repository. The short-lived Fulcio certificate in the bundle is logged in
> Rekor's public transparency log, making the signing event auditable.

### 3. SBOM

Each archive ships an SPDX-JSON SBOM (`<archive>.sbom`), also listed in
`checksums.txt`. Inspect it with any SPDX-aware tool:

```bash
# Verify the SBOM's checksum first
sha256sum --check checksums.txt --ignore-missing

# Scan for known vulnerabilities
grype sbom:./kafkamcp_<version>_linux_amd64.tar.gz.sbom
```

The SBOM is generated by syft during the GoReleaser run and covers the Go module
dependency tree of the released binary.

### 4. Build provenance (GitHub attestations)

Requires [GitHub CLI ≥ 2.49](https://cli.github.com/).

```bash
gh attestation verify kafkamcp_<version>_linux_amd64.tar.gz \
  --repo josedab/kafkamcp
```

This verifies the SLSA provenance attestation attached to the artifact by
`actions/attest-build-provenance@v3` during the release workflow. It confirms
the binary was built from the expected commit in the `josedab/kafkamcp`
repository, without requiring any long-lived keys.

You can also verify the checksum file itself:

```bash
gh attestation verify checksums.txt \
  --repo josedab/kafkamcp
```

### 5. Container signature and provenance

Release images use immutable version tags; pre-releases never move a `latest`
tag.

```bash
IMAGE=ghcr.io/josedab/kafkamcp:<version>

cosign verify "$IMAGE" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/josedab/kafkamcp/\.github/workflows/release\.yml@.*$'

gh attestation verify "oci://$IMAGE" --repo josedab/kafkamcp
```

## Notes

- Pages/website deployment requires GitHub Pages to be enabled for the repository
  (Settings → Pages → Source: GitHub Actions). The workflow is buildable
  regardless; only the publish step needs the setting.
- No secrets or long-lived keys are stored in the repository. Signing relies on
  the ephemeral GitHub OIDC token and Sigstore's transparency log.
- `make security` is release-gating: it runs the pinned gosec policy (all
  high-severity, high-confidence findings block) and `govulncheck`. The complete
  gosec JSON remains available as a CI artifact for advisory findings.
- `make helm-check` lints and renders production scenarios, including probe
  wiring, durable SQLite PVCs, singleton safety, and telemetry egress.
